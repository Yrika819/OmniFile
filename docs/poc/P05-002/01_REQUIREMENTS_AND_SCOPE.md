# P05-002 Requirements and Scope

`POC-ONLY — NOT PRODUCTION AUTHORITY`

## Source requirements

This POC is the disposable evidence harness for POC-002 in `docs/architecture/12_POC_BACKLOG.md`. The applicable architecture requires:

- durable operation state independent of an Android executor or process lifetime;
- reconciliation after restart rather than blind replay;
- inspection of actual partial/final destination state;
- validation of source/version/checkpoint assumptions;
- explicit classification as resumable, restart-required, conflicted, already-completed, cancelled, or failed;
- no source deletion before destination verification/finalization for a move;
- bounded I/O and no assumption that a SAF URI is a filesystem path.

## Evidence question

Can a small policy model classify deterministic recovery conditions when durable checkpoint metadata and provider reality disagree, while preserving the source-deletion boundary?

## In scope

- Opaque provider-scoped locators shaped like `content://p05/<id>`.
- In-memory source, partial-destination, and final-destination state.
- A durable operation record containing operation kind, source version, expected content digest, phase, and checkpoint bytes.
- Fault injection for checkpoint lag, provider disconnect, grant revocation, partial mismatch, and finalization acknowledgement loss.
- Pure reconciliation decisions with explicit next actions.
- Host-side standard-library tests using generated byte strings only.

## Out of scope

- Android `ContentResolver`, `DocumentsContract`, `DocumentFile`, `DocumentsProvider`, or URI-permission APIs.
- An Android application, manifest, Gradle project, production module, dependency selection, or target/min SDK decision.
- A claim about provider flags, file descriptors, seeking, atomic rename, persistable grants, process death, power loss, or device UX.
- A real filesystem copy, deletion, emulator, physical device, ADB, cloud account, removable media, or user data.
- Automatic retry, automatic source deletion, or a durable database implementation.

## Success criteria

The focused host test suite must prove that:

1. observed partial bytes, when valid, take precedence over a stale smaller checkpoint;
2. a revoked grant or disconnected provider blocks recovery instead of replaying blindly;
3. mismatched partial bytes require restart/conflict handling;
4. an observed finalized destination does not cause reconciliation to delete a move source;
5. an incomplete or unverifiable destination never produces a completion decision.

The suite is evidence for policy shape only. Android and physical-device validation remain separate gates.
